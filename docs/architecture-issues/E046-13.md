## Instrukcja wykonania krok po kroku

1. Odczytaj shadow_prepare, shadow_map_cache, scene_bridge, render i world_geometry_gpu. Wypisz operacje CPU (wybór, local_map_geometry, bounds, uniform) i GPU (allocate/upload/release/encode) wraz z właścicielem.

2. Wydziel proponowany CPU kontrakt PreparedShadowFrame zawierający context/publication identity, wybrane keys, uniform oraz przygotowaną geometrię lub jawne polecenie reuse cache. Typ nie zawiera device/queue/buffer/session. Przyczyna invalidation jest częścią wyniku.

3. Przenieś local_map_geometry i sector_geometry_relative z impl GpuResources do CPU preparera. Wymagane bounds/wersje dostarczaj przez read-only snapshot danych sceny, nie mutowalnego właściciela GPU. Zachowaj dotychczasowe progi, radius i limit geometrii.

4. Zastąp mutujące update_shadow_map_vertices w preparerze wynikiem danych. GPU owner ma upload_prepared_shadow z kontrolowanym wynikiem Ready/Pending/Failed; zapisuje cache metadata dopiero po udanym kompletnym uploadzie. Niepowodzenie nie publikuje częściowej nowej sceny jako kompletnej.

5. Złóż immutable scene/frame description przed encode. GPU render aplikuje uploady i uniform, sprawdza gotowość oraz używa wyłącznie opisu i własnych zasobów. Stare bufory mogą pozostać aktywne tylko z odpowiadającym im pełnym opisem; mieszanie rewizji unieważnia cień.

6. Zrób jeden release_world punkt dla wszystkich buforów świata i zależnych cache. Zawęź pola GPU do prywatnych właścicieli i metod; przełącz callerów przed usunięciem publicznych pól.

7. Usuń nieużywane importy po refaktorze, uaktualnij zakres timera shadow_prepare_cpu, przejrzyj CPU-only feature boundary RenderFrame. Zapisz źródłową listę wszystkich callerów nowego kontraktu; dalsze znaczniki spójności dopracuj w E046-14.
