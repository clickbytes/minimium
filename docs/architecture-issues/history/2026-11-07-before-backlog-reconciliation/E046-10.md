# E046-10 — Potwierdzić shutdown z rzeczywistym wynikiem zapisu

## Powiązania GitHub

Epic nadrzędny: https://github.com/clickbytes/minimium/issues/347

Zależności do zakończenia źródłowego: [E046-04](https://github.com/clickbytes/minimium/issues/351), [E046-07](https://github.com/clickbytes/minimium/issues/354), [E046-09](https://github.com/clickbytes/minimium/issues/356).


Priorytet P0. Krok 33. Właściciele: platform, aplikacje, runtime’y, storage, telemetry. Zależności: E046-04/07/09.

Gdzie: `apps/server/src/main.rs`, `crates/platform/src`, `crates/server-runtime/src/lifecycle.rs`, `crates/storage/src/persistence/`, bootstrap client-runtime, `apps/client/src/renderer/controller.rs`.

Zakres: zmapować sygnał ctrlc/termination, admin stop i zamknięcie właściciela do jednego ShutdownRequest. Udowodnić kolejność stop admission→freeze mutations→stop jobs→capture→save→release endpoint→logs. Całość 30 s, logi do 2 s w tym budżecie. Przejrzeć każdy Drop/send/recv/join: brak bezterminowych operacji, jawna lista niezakończonych workerów, timeout zapisu nie jest sukcesem ani dowodem anulowania I/O. Klient zatrzymuje wyłącznie OwnedServer.

Akceptacja: wynik końcowego zapisu dociera do exit status; wszystkie workery ujęte w tabeli lifecycle; poprzedni atomowy snapshot chroniony. Zachowanie sygnałów pozostaje do odrębnych scenariuszy runtime.

## Instrukcja wykonania krok po kroku

1. Zrób inwentarz workerów: sektor, kolizja, content preparation/download, HTTP, persistence, telemetry i connector/local server. Dla każdego zapisz owner, handle, kanał stop i sposób odebrania końcowego wyniku.

2. W entrypointach i platformowym handlerze sygnału przeprowadź ctrlc/termination do ShutdownRequest; callback sygnału jedynie ustawia żądanie. Admin stop i owned process close muszą ustawiać ten sam mechanizm.

3. W lifecycle wprowadź jeden absolutny deadline start+30 s przekazywany do kolejnych faz. Zarezerwuj końcowe 2 s dla logów wewnątrz tego deadline; nie przyznawaj osobnych pełnych 30 s każdemu workerowi.

4. Zamknij admission i nowe mutacje, zatrzymaj przyjmowanie prac, capture final snapshot, poczekaj ograniczenie na wynik zapisu, zwolnij endpoint, zamknij logi. Potwierdź final snapshot z E046-07, którego nie wolno zastąpić autosave.

5. Zastąp bezterminowe send/recv/join w Drop nieblokującym żądaniem stop lub cleanup bez oczekiwania. Jawne shutdown_until zbiera niezakończone worker ID i wynik save. Nie udawaj przerwania blokującego OS I/O po timeout.

6. W aplikacji zmapuj timeout/error zapisu na niezerowy exit; zachowaj poprzedni atomowy snapshot. W kliencie sprawdź ownership przed kill/stop: AttachedServer nie może być zatrzymany. Dopisz tabelę kolejności i wyników wszystkich ścieżek shutdown.
