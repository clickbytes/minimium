Wykonać dokładnie w kolejności:

1. Zaktualizować Cargo.lock tylko dla potrzebnych zależności, bez zbiorczego upgrade.
2. Sformatować zmieniony Rust.
3. `rtk python scripts/check_file_lengths.py`
4. `rtk python scripts/check_architecture.py`
5. `rtk python scripts/check_static_refactor.py`
6. `rtk cargo build --workspace --all-targets --all-features --locked`
7. `rtk cargo build -p minimium-client --no-default-features --locked`

Każdy błąd naprawić u właściciela; po zmianie ponowić dotknięte kontrole. Nie wyłączać targetów/features, nie dodawać atrap ani szerokich wyciszeń. `--all-targets` kompiluje istniejące testy, ale ich nie uruchamia. Nie uruchamiać cargo test, gry, loadtestu ani benchmarków.

Akceptacja: wszystkie polecenia zakończone sukcesem na końcowym stanie drzewa, zapis rzeczywistych wyników i ograniczeń. Nie zastępować pełnego builda sprawdzeniem jednego crate.

## Instrukcja wykonania krok po kroku

1. Przed poleceniami przejrzyj raporty 01–16. Jeśli choć jeden wymagany kontrakt, konsument lub dokumentacja jest niedokończona, wróć do jego issue. Zapisz git status/HEAD i stan untracked, aby wyniki odnosiły się do konkretnego drzewa.

2. Rozwiąż lockfile dla dodanych zależności przy zachowaniu istniejących wersji, gdzie możliwe. Przejrzyj diff Cargo.lock i cofnij tylko własne niepowiązane aktualizacje. Nie uruchamiaj bezwarunkowego cargo update całego workspace.

3. Uruchom formatowanie Rust przez rtk cargo fmt --all; przejrzyj diff i nie zostaw niepowiązanych zmian. Po podziale zbyt długiego pliku popraw module declarations i callerów, nie kompresuj kodu.

4. Wykonaj trzy skrypty oraz dwa buildy i WGSL dokładnie w kolejności podanej w głównym opisie issue. Dla każdego zapisz polecenie, exit code i istotną diagnostykę w raporcie. All-targets kompiluje testy, nie uruchamia ich.

5. Jeśli proces nadal działa, zachowaj handle i odpytuj ten sam proces. Błąd napraw u właściciela, nie usuwaj targetu/feature/limitów. Po zmianie API ponów oba buildy; po shaderze WGSL i właściwy build; po zależnościach także architekturę i locked builds.

6. Po ostatniej poprawce potwierdź, że wszystkie wyniki dotyczą końcowego drzewa. Wykonaj końcowy git diff --check/status, sprawdź brak zmian concat.txt i brak przypadkowych artefaktów. Nie wykonuj commit/push ani testów uruchomieniowych.
