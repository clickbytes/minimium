# B01 — Wyłączna własność katalogu serwera

Status: odebrane

ID i powiązane kryteria epica: B01, #7/#10/#12; szczegóły w macierzy.

Cel: Wyłączna własność katalogu serwera.

Zależności: K00.

Pliki do odczytu: crates/core/src/endpoint.rs; apps/server/src/main.rs atomic_replace_file.

Pliki do zmiany — zamknięta lista: crates/core/src/server_lock.rs; crates/core/src/endpoint.rs.

Istniejące symbole i miejsca integracji: ServerEndpoint::{read,write}; start run.

Ustalony kontrakt wejścia/wyjścia: ServerDataLock::acquire(&Path)->io::Result<Self>, trzyma File; ServerEndpoint::remove_if_owned(&self,&Path)->io::Result<()>; atomic_replace_file udostępnia koordynator.

Wymagane zachowanie i limity: server.lock open bez truncate, File::try_lock; uchwyt RAII bez usuwania lock; read endpoint max 256 B+1, reject excess; temp+atomic replace; zgodność 3 linii; sprzątanie po tokenie/portach.

Warunki odbioru implementacji: Drugi serwer nie mutuje danych; wszystkie wyjścia zwalniają lock; stare endpointy czytelne.

Scenariusze późniejszej weryfikacji: Dwa równoczesne serwery, awaria startu, podmiana endpointu.

Zakazane rozszerzenia zakresu: zmiana protokołu v8/zapisu v3, testy i obciążenie, nowe funkcje poza kontraktem, commity/push/GitHub, cudze pliki. Unsafe, manifesty, moduły i integrację pętli wykonuje koordynator. Nie uruchamiaj cargo workspace ani cargo fmt --all. Raportuj zależności zamiast edycji cudzych plików.


Raport i odbiór koordynatora: [review.md](../review.md); kontrole [verification.md](../verification.md). Przebieg: gotowe do przydzielenia → w pracy → do przeglądu → odebrane. Scenariusze działania nieuruchomione.
