# S02 — Wspólny dispatcher i ograniczone komendy

Status: odebrane

ID i powiązane kryteria epica: S02, #4/#7; szczegóły w macierzy.

Cel: Wspólny dispatcher i ograniczone komendy.

Zależności: S01.

Pliki do odczytu: apps/server/src/main.rs execute_command, handle_admin; core commands.

Pliki do zmiany — zamknięta lista: apps/server/src/commands.rs; apps/server/src/terminal.rs.

Istniejące symbole i miejsca integracji: ServerCommand, PersistenceWorker, World.

Ustalony kontrakt wejścia/wyjścia: CommandContext{world:&World,player_store:&mut PlayerStore,persistence:&mut PersistenceWorker,map_fingerprint,lanes,metrics:&RuntimeMetrics}; execute(ServerCommand,CommandContext)->CommandReply{success,text,stop}; terminal spawn -> Receiver<ServerCommand>. Koordynator: wspólna kolejka 64,8/tick.

Wymagane zachowanie i limity: Terminal max512 B bez nieograniczonego read_line; try_send overflow ERR; wszystkie6 komend identyczne; players lista; stop reply przed save; przed simulation.

Warunki odbioru implementacji: Jeden dispatcher; bounded queues; jawne overload.

Scenariusze późniejszej weryfikacji: Flood terminal/admin, stop, world save busy/error.

Zakazane rozszerzenia zakresu: zmiana protokołu v8/zapisu v3, testy i obciążenie, nowe funkcje poza kontraktem, commity/push/GitHub, cudze pliki. Unsafe, manifesty, moduły i integrację pętli wykonuje koordynator. Nie uruchamiaj cargo workspace ani cargo fmt --all. Raportuj zależności zamiast edycji cudzych plików.
